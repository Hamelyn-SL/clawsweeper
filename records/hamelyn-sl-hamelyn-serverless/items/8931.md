## Label Justifications

- `P1`: La rama puede mantener listings confirmados fuera de create y dejar indisponible el mirror analítico tras el despliegue.

## Summary

Gracias por la contribución: el objetivo V2 está bien acotado, pero la rama aún puede dejar cohortes `DB_ONLY` fuera de create, reclasificar filas recientes o romper el mirror de BigQuery sin una migración aplicada.

## What This Changes

El PR sustituye estados V1 en tres reportes, limpia metadatos al reactivar filas y añade campos V2 al materializado diario e histórico de BigQuery.

## Best Possible Solution

Crear una mutación específica de reconciliación `DB_ONLY` que borre el error V2 con filtros CAS y frescura, añadir `retryPolicy` al contrato analítico y desplegar el DDL antes de activar las queries.
