## Summary

Gracias por el reporte. La capacidad multi-bulto ya existe al cambiar desde `SPRING` o `SEUR` a FedEx, pero los pedidos cuyo carrier original es `FEDEX` siguen sin acceso a esa acción; esta ampliación continúa pendiente.

## What This Changes

La petición solicita permitir varios bultos y generar varias etiquetas FedEx para un mismo envío de pedido múltiple.

## Best Possible Solution

Reutilizar el constructor multipieza para pedidos `FEDEX` y definir una transición atómica de etiqueta, tracking y archivos asociados.

Rationale: La elección cambia el tracking y los documentos ya persistidos; la ruta actual solo cambia desde otros carriers.

Likely owner: Miguel Angel Hernández Perdomo

Owner confidence: high

Options:

- **Regenerar como multipieza (recommended):** Invalidar la etiqueta anterior y persistir un único envío FedEx multipieza como fuente de verdad.
- **Conservar el primer bulto:** Añadir piezas bajo el tracking existente solo si el contrato FedEx y los datos almacenados lo permiten.

## Reproduction Assessment

Sí, por código: con `originalCarrier: "FEDEX"`, la tabla de destinos no devuelve objetivo y el control de bultos no se renderiza.

## Solution Assessment

No todavía: reutilizar la ruta multipieza es la solución más estrecha, pero falta decidir el destino de la etiqueta FedEx ya creada.
