## Summary

Gracias por el contexto. Mantendría esta issue abierta: el comportamiento actual conserva la retirada como pendiente cuando falla la búsqueda, pero no hay decisión sobre adelantar el reintento y no se conoce la causa del 403; la ausencia de recurrencia observada no resuelve ninguna de las dos cuestiones.

## What This Changes

Solicita ampliar el diagnóstico permitido del 403 de MercadoLibre y valorar reintentos de búsqueda más frecuentes sin confirmar la retirada hasta completar ambas búsquedas.

## Best Possible Solution

Mantener la regla de confirmación estricta y acordar con el responsable de la integración una política acotada de reintentos para fallos exclusivamente 403; ampliar el registro solo con códigos saneados que no expongan datos sensibles.

Required: true

Kind: product_direction

Question: ¿Debe una búsqueda de retirada fallida exclusivamente con 403, tras cerrar correctamente el anuncio conocido, reintentarse antes que el backoff transitorio actual?

Rationale: La opción de cinco minutos reduce el retraso, pero un rechazo sostenido incrementaría llamadas; el repositorio no documenta un límite operativo aprobado para este caso y la causa externa sigue sin identificarse.

Likely owner: MarcosTerroso

Owner reason: Su historial de cambios en los diagnósticos y la política de búsquedas incompletas lo sitúa como candidato de referencia para valorar este comportamiento.

Owner confidence: medium

Options:

- **Adelantar con límite (recommended):** Aplicar un intervalo menor acotado solo a búsquedas fallidas exclusivamente con 403 tras un cierre correcto, manteniendo la retirada pendiente hasta completar ambas búsquedas.
- **Mantener el backoff:** Conservar el primer reintento de una hora y reconsiderarlo si reaparecen los fallos o se verifica un anuncio hermano todavía vendible.
- **Definir el presupuesto primero:** Esperar a disponer de un ejemplo saneado del rechazo y acordar el techo de llamadas antes de cambiar el intervalo.

## Reproduction Assessment

Sí, el camino se puede reproducir en código al hacer que una búsqueda por estado devuelva 403: la retirada queda incompleta y sigue el backoff transitorio. No se reprodujo el rechazo real del proveedor ni se verificaron anuncios hermanos en producción.

## Solution Assessment

Parcialmente: conservar la retirada incompleta es la solución segura y ya está implementada; reducir el backoff puede aliviar la demora, pero necesita límites operativos acordados y no explica el 403.
