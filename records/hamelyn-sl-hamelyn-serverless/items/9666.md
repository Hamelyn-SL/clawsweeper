## Label Justifications

- `P0`: El código actual permite que rutas administrativas v5 alcancen operaciones sensibles sin pasar por una capa de autenticación o roles.
- `impact:security`: El alcance afecta directamente a verificación de identidad, audiencia de token y autorización por rol.

## Summary

Esta incidencia sigue siendo necesaria: `dev` mantiene rutas v5 administrativas que alcanzan lógica mutante sin autorización y una política que permite listas de roles vacías. Requiere una decisión de límite de seguridad para no interrumpir los flujos de almacén no interactivos.

## What This Changes

Proteger rutas administrativas v4 y v5 frente a llamadas sin autenticación o sin roles explícitos.

## Best Possible Solution

Crear un perímetro único para `/api/v5/admin` y `/api/v5/revision`, denegar listas de roles vacías y migrar las excepciones operativas a identidades de servicio o callbacks firmados con permisos mínimos.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: ¿Qué contrato autenticado debe sustituir las llamadas no interactivas de almacén antes de exigir roles explícitos en todas las rutas administrativas?

Rationale: El código demuestra la exposición, pero elegir identidad de servicio, callback firmado u otro contrato depende de consumidores desplegados que el repositorio no describe.

Likely owner: JavierHamelyn

Owner reason: Está asignado y ya delimitó los flujos operativos que condicionan el cambio.

Owner confidence: high

Options:

- **Identidades de servicio (recommended):** Migrar procesos no interactivos a credenciales de servicio con permisos mínimos y exigir roles a las rutas de usuario.
- **Callbacks firmados:** Permitir callbacks con firma verificable únicamente en rutas concretas y documentadas.
- **Excepciones temporales:** Mantener rutas específicas sin roles durante la migración y aceptar temporalmente el riesgo de seguridad.

## Reproduction Assessment

Sí en código: varias rutas v5 llegan a controladores sin wrapper ni proxy, y las listas vacías conceden acceso a cualquier token válido. Falta confirmar el efecto contra un staging operativo y aislado.

## Solution Assessment

No como cambio global inmediato: la solución debe cerrar el perímetro y sustituir primero las excepciones operativas por contratos autenticados específicos.
