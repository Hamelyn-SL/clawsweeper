## Summary

La incidencia sigue siendo necesaria: el código de `dev` aún aborta la selección de un cliente no registrado, pero una PR abierta y vinculada propone el arreglo completo.

## What This Changes

Permitir que el watcher B2B publique un dry-run provisional para clientes no registrados, bloqueando toda ejecución real hasta su alta en `B2B_CLIENTS`.

## Best Possible Solution

Aterrizar una separación explícita entre cliente provisional de solo lectura y cliente registrado ejecutable, con pruebas de rechazo en reacción, tool HITL y `executeOrder`.

## Solution Assessment

Sí, la separación entre perfil provisional solo de selección y cliente registrado ejecutable resuelve el bloqueo sin relajar las mutaciones B2B.
