## Summary

La incidencia sigue siendo necesaria: el watcher registra el cliente desconocido, pero `computeSelection` aborta antes de descargar el pedido y publicar el dry-run. La separación propuesta entre selección provisional y ejecución registrada es acotada y mantiene el flujo operativo seguro.

## What This Changes

Permitir que el watcher B2B publique el dry-run y los dos CSV para clientes no registrados mediante una configuración provisional derivada del título, sin permitir su ejecución real.

## Best Possible Solution

Introducir un tipo o marca explícita de cliente provisional solo para selección, publicar el dry-run y escalar el alta pendiente; toda ruta mutante debe exigir un cliente registrado antes de crear BPs o retirar stock.
