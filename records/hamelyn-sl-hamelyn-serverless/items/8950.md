## Label Justifications

- `P1`: El cambio aborda una regresión de retirada de marketplace que puede ocultar desenlaces de stocks vendidos.
- `merge-risk: 🚨 other`: Un contador de reconciliación incorrecto puede ocultar fallos de persistencia o hacer que un SKU parezca tener dos desenlaces.

## Summary

La corrección cubre el contador `batched`, pero mantiene un resumen incorrecto cuando falla el aparcado de un huérfano; además, la evidencia publicada sigue siendo un harness simulado, no un flujo Mirakl/Mongo real.

## What This Changes

La rama añade `batched` al resumen de retirada y devuelve `PERSISTENCE_FAILED` cuando no puede persistir el error de un stock sin `marketplaceId`.

## Best Possible Solution

Contar `orphansParked` solo tras persistir el error, añadir una regresión que valide el resumen y aportar una ejecución redactada contra el flujo operativo antes del merge.
