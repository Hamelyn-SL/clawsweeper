## Summary

La incidencia sigue siendo necesaria: el precheck reabre toda canónica cerrada al detectar la firma, sin comprobar si el PR que la cerró llegó a `master` ni si la observación es posterior al despliegue.

## What This Changes

Añadir una guarda de despliegue al marketplace watcher para no reabrir incidencias cerradas por fixes aún no incluidos en producción.

## Best Possible Solution

Resolver el PR de cierre hasta su merge commit, bloquear reapertura y estancamiento mientras no esté en producción, y aceptar solo evidencia posterior a su entrada efectiva.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, con alta confianza desde código: una canónica cerrada y una firma sobre umbral recorren `precheck.ts` hasta `reopen` sin consultar el despliegue. El caso de 11 de septiembre aportado en la discusión confirma esa ruta en producción.

## Solution Assessment

Sí, una guarda basada en el commit de cierre y su entrada efectiva en producción es más precisa que usar solo el estado `merged`. Debe cubrir también la excepción anti-estancamiento y mantener la reapertura para evidencia posterior válida.

## Repair Work Prompt

Corrige el marketplace watcher para que no reabra una issue cerrada por un PR que solo está mergeado en `dev`. Amplía la consulta GitHub para resolver el PR de cierre, su merge commit y el instante de entrada en `master` o un despliegue verificable de `marketplace-crons`. Antes de `reopen` y al evaluar estancamiento, ignora evidencia anterior a ese instante; si el fix sigue pendiente de despliegue, no reabras y conserva un único estado/comentario `phase=pending-deploy` idempotente. Mantén la reapertura para recurrencias posteriores válidas y documenta la regla. Añade pruebas de PR dev-only, evidencia previa al despliegue y evidencia posterior. No cambies límites OF24, consultas BigQuery ni `CHANGELOG.md`.
