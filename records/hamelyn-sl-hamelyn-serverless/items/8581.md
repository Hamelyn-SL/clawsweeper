## Label Justifications

- `P1`: Una reconciliación incompleta o repetida puede afectar pedidos reales de marketplace en cada cron.
- `merge-risk: 🚨 compatibility`: La rama actualiza el protocolo Order Update y modifica la prioridad asignada a pedidos existentes.

- `merge-risk: 🚨 other`: El barrido por ventana puede omitir cancelaciones antiguas o posteriores al tope y alterar fechas de cancelación.

## Summary

El enfoque reduce llamadas a AbeBooks, pero la rama mantiene regresiones que pueden dejar cancelaciones sin reconciliar o reescribir su fecha. La prueba publicada también confirma solo tests, no el flujo remoto decisivo.

## What This Changes

El PR añade `searchOrders` para detectar cancelaciones de AbeBooks, sube la API Order Update a v1.3 y usa `shipping.speed` para elevar la prioridad de envío.

## Best Possible Solution

Conservar una recuperación para pendientes locales, paginar de forma progresiva, hacer idempotentes las transiciones y resolver IDs en lotes antes de aprobar la política de prioridad v1.3.
