## Summary

El cambio aborda una necesidad real de identidad por mercado, pero `x-hamelyn-market` se acepta en rutas API que el propio PR indica que pueden evitar el proxy. Como una petición externa puede enviar esa cabecera, el cambio permite seleccionar la identidad de cualquier mercado delegado sin validar que el proxy la haya establecido; hace falta cerrar esa frontera antes de integrar.

## What This Changes

El PR resuelve la identidad de ecommerce por petición y propaga locale, moneda, país y host por las rutas de servidor y los componentes cliente.

## Best Possible Solution

Conservar la resolución por mercado, pero aceptar la identidad delegada solo cuando exista una señal de confianza que una petición externa no pueda falsificar; mantener el host legacy como fallback y añadir cobertura de rutas API directas.
