## Label Justifications

- `P1`: Puede dejar un listing comprable tras retirar el stock interno, con riesgo de sobreventa y cancelaciones.
- `impact:other`: Afecta la coherencia operativa entre el stock interno y un listing externo de marketplace.

## Summary

El comportamiento actual sigue permitiendo que un fallo de `active` quede oculto si `paused` devuelve ids; la retirada puede continuar sin haber resuelto el listing comprable.

## What This Changes

Evitar que un error parcial de `items/search` por estado permita confirmar una retirada de MercadoLibre dejando un listing activo sin cerrar.

## Best Possible Solution

Definir un contrato de retirada que no confirme éxito con estados vivos sin resolver y añadir regresión para `active` fallido con `paused` correcto.

Options:

- **Abortar la retirada parcial (recommended):** Propagar el fallo y dejar el stock reintentable hasta resolver ambos estados vivos.
- **Cerrar lo conocido y reintentar:** Cerrar únicamente el id seguro, registrar una anomalía estructurada y no confirmar una retirada completa hasta recuperar el estado pendiente.

## Reproduction Assessment

Sí, desde código: simular `active` fallido y `paused` con ids hace que `findLiveItemIdsBySku` devuelva éxito sin propagar el error de `active`.

## Solution Assessment

No concluyente: el defecto está acotado, pero elegir entre abortar o permitir un cierre degradado auditable requiere decisión operativa.
