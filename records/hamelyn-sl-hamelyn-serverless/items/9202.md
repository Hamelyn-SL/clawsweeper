## Label Justifications

- `P1`: Los defectos pueden desalinear operaciones de picking activas, huecos físicos y datos de venta.
- `merge-risk: 🚨 compatibility`: El endpoint puede confirmar una operación B2B distinta si el SKU aparece en más de una operación.
- `merge-risk: 🚨 session-state`: El estado `DONE` puede persistirse antes de completar sus efectos asociados, sin reanudación posterior.
- `merge-risk: 🚨 availability`: Fallos transitorios pueden impedir que Station confirme o calcule de forma segura el siguiente hueco.

## Summary

El enfoque de servicio compartido responde al problema de la incidencia vinculada, pero el PR deja varias rutas confirmadas que pueden desalinear el picking, los huecos y los datos de venta.

## What This Changes

El PR confirma líneas Skypod desde Station mediante un servicio compartido y transforma el webhook de Exotec en una vía de verificación.

## Best Possible Solution

Conservar el servicio común, pero exigir una señal inequívoca de éxito para avances externos y hacer recuperables, idempotentes y probados todos los efectos posteriores al claim.

- **Aceptar la inferencia actual:** Mantener la inferencia por `article_id` y documentar que los errores externos pueden consumir huecos que luego requieren revisión.

Sí, por código: basta forzar un error posterior al claim, un fallo del POST o una respuesta nula de hueco para seguir las rutas que impiden reparar o repetir la confirmación.
