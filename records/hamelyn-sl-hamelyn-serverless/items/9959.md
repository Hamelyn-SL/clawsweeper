## Summary

El PR aporta la fase de PAT y catálogo, pero bloquea las mutaciones con un PAT que solo tenga `write:dashboards`: el proxy las preautoriza como `GET` y exige `read:dashboards` antes de llegar a la ruta.

## What This Changes

Añade scopes de Data Dashboards para PAT del CLI, autenticación reutilizable en core y un catálogo autenticado de gráficas y endpoints.

## Best Possible Solution

Hacer que la preautorización conserve el método HTTP original, cubrir el recorrido proxy→ruta con PAT de solo escritura y mantener intactas las rutas JWT y MCP.
