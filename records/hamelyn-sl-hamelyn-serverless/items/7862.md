## Summary

Se mantiene abierta: `dev` aún recarga configuración en cada reutilización warm y recicla el pool al fallar; la única propuesta vinculada se cerró sin merge y no preservaba con seguridad `mongo_user_id`.

## What This Changes

Evitar reconexiones masivas durante refrescos lentos de configuración Mongo y desacoplar de forma segura Supply Analytics de Mongo.

## Best Possible Solution

Corregir primero el refresco warm con TTL, single-flight y stale-on-error, conservando el enriquecimiento actual hasta aprobar un reemplazo asíncrono para `mongo_user_id`.
