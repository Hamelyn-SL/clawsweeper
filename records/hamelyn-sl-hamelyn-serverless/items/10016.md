- `P2`: El dato afecta la atribución de costes y consultas dependientes de `orderId`, con alcance amplio pero impacto analítico y corrección ya propuesta.
- `impact:data-loss`: El proceso sobrescribe `orderId` materializados con NULL y deja referencias históricas recuperables sin informar.

## Summary

La causa está confirmada en el materializador actual y la discusión acredita referencias afectadas; la corrección sigue en una PR abierta, sin despliegue ni recuperación histórica confirmados, así que esta incidencia debe permanecer abierta hasta verificar ambos.

## What This Changes

El materializador de stocks interpreta `order` solo como estructura y deja `orderId` a NULL cuando el dato llega como texto hexadecimal.

## Best Possible Solution

Aceptar el formato hexadecimal sin perder compatibilidad con la estructura histórica y, tras el despliegue, rellenar las referencias recuperables con una operación acotada y autorizada, verificando el siguiente ciclo de materialización.

Required: false

## Reproduction Assessment

Sí, el flujo actual es reproducible desde el código: si `order` es texto, las extracciones de sus subcampos producen NULL y el MERGE actualiza `orderId` con ese resultado; la consulta de triage aporta además mediciones del espejo.

## Solution Assessment

Sí, aceptar ambos formatos en la expresión existente es una corrección acotada; para resolver el impacto completo también hace falta verificar el relleno histórico, ya que la ventana incremental no cubre necesariamente filas antiguas.
