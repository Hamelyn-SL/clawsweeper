## Label Justifications

- `P2`: Queda un error acotado de productividad en la recepción de lotes con varios bultos cuando falla el primer escaneo.

## Summary

El caso de cero escaneos sigue sin repartir el crédito como un bulto implícitamente recibido: el mínimo actual abona 1 artículo, no la parte proporcional. El último comentario de revisión confirma que aún deja el lote en 2/3 y solo 42/64 artículos acreditados.

## What This Changes

El PR reparte la productividad de recepción entre los bultos escaneados inicialmente y los que llegan después, y actualiza la API, el panel y la documentación del flujo.

## Best Possible Solution

Aplicar al cálculo una regla coherente para el primer bulto confirmado aunque su POST no se haya registrado, y comprobar con una prueba que 64 artículos y 3 bultos terminan acreditando 21/21/22 sin superar el total.

Sí, el camino está concretado en la revisión: en un lote de 64 artículos y 3 bultos, falla el POST del primer escaneo y se declaran dos faltantes; el código actual acredita solo 1 artículo al declarar.

## Solution Assessment

No todavía: el reparto proporcional propuesto es adecuado, pero el caso de cero escaneos debe tratar el primer bulto confirmado como parte del crédito inicial y contar con cobertura que verifique el reparto final.
