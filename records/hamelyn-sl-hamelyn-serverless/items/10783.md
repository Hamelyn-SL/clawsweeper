## Label Justifications

## Summary

El fallo descrito es plausible: el run `edited` de un borrador omite la guarda, pero el run posterior cuenta cualquier ejecución anterior activa de la misma PR. No hay un arreglo merged que lo resuelva; conviene mantener el issue abierto.

## What This Changes

La guarda de asignación de reviewer puede tratar un run previo que no podía solicitar reviewer como si ya estuviera gestionando esa asignación.

## Best Possible Solution

Mantener la protección frente a asignaciones duplicadas, pero contar solo ejecuciones previas que podían alcanzar el paso de asignación de reviewer.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, la ruta es reproducible por inspección del workflow: un run activo de `edited` en borrador aparece en la consulta de runs, aunque no haya ejecutado la guarda ni pueda asignar reviewer; después el evento `ready_for_review` puede omitir la asignación.

## Solution Assessment

Sí. La corrección más acotada es filtrar las ejecuciones previas por su evento y elegibilidad para el reviewer, preservando la protección contra solicitudes duplicadas.
