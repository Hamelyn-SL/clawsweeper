## Label Justifications

- `P1`: El bloqueo mantiene listings de stock vendido activos en un marketplace y afecta un flujo operativo real.
- `merge-risk: 🚨 other`: La nueva política global de selección puede retrasar operaciones no prioritarias bajo una carga continua de retiradas.

## Summary

El PR sigue siendo necesario: `dev` conserva el FIFO por antigüedad que bloquea retiradas. La corrección es acotada y un revisor humano ya confirmó la prioridad absoluta como la opción acordada para este caso.

## What This Changes

El PR calcula una prioridad por grupo batch para seleccionar `withdraw` antes de `publish` y `reprice`, manteniendo FIFO dentro de cada nivel.

## Best Possible Solution

Integrar la prioridad por grupo y monitorizar los contadores de `publish` y `reprice`; si aparece inanición sostenida, abrir un seguimiento separado para una cuota por operación.

Sí. La incidencia aporta datos de la cola real y Proof Agent reprodujo el fallo con 39 grupos: la base no selecciona retiradas y el SHA actual sí.

## Solution Assessment

Sí. Priorizar por grupo antes de aplicar el límite resuelve directamente el bloqueo FIFO y conserva el orden cronológico dentro de cada prioridad.
