## Summary

Gracias por el contexto: la incidencia sigue siendo necesaria porque `dev` acepta y propaga un PAT no vacío sin comprobar que GitHub permita `workflow_dispatch`, dejando parada la familia compartida `gh-dispatch` si la credencial es inválida.

## What This Changes

La incidencia solicita restaurar el PAT que despacha los crons de Cloud Scheduler y añadir una validación preventiva antes de aplicar Scheduler.

## Best Possible Solution

Restaurar primero un PAT aprobado, reaplicar Scheduler y confirmar un dispatch real; después incorporar una comprobación aislada que valide `Actions: write` antes del apply.
