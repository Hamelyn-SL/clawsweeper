## Label Justifications

- `P1`: La corrección afecta a un flujo de staging que puede dejar los watchers contra código antiguo o hacerlos fallar.
- `merge-risk: 🚨 compatibility`: El alias de `dev` puede acabar apuntando a un deployment distinto del commit desplegado.
- `merge-risk: 🚨 security-boundary`: La nueva credencial de Vercel se hereda por todo el job en vez de limitarse al paso de deploy.

## Summary

El PR aborda una incidencia real de staging, pero todavía puede conservar o redirigir el alias a un build incorrecto; necesita correcciones y prueba real antes de merge.

## What This Changes

El PR añade una espera del deployment de Vercel y asigna explícitamente el alias de `dev` de `agents` después del deploy hook de staging.

## Best Possible Solution

Hacer obligatoria una credencial de alcance mínimo en el paso final, seleccionar el deployment por `GITHUB_SHA` y adjuntar una prueba saneada de que el alias apunta al deployment recién creado.
