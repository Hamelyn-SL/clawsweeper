## Summary

El cambio aborda los casos descritos, pero la marca de rechazo de memoria es global: una sincronización aceptada con otro token puede borrarla y reactivar los hooks con el token antiguo. Conviene corregir ese caso antes de dar por revisado el PR.

## What This Changes

El PR añade avisos de permisos y gestión de tokens rechazados en el CLI, registra el principal de ciertos 403 de la API y actualiza pruebas y documentación.

## Best Possible Solution

Mantener la marca asociada al token rechazado y borrarla solo cuando ese mismo token se confirme aceptado, con cobertura para el token guardado y una sustitución temporal vía `HAMELYN_TOKEN`.
