## Label Justifications

- `P2`: El guard evita una caché corrupta, pero los conteos de catálogo pueden quedar desactualizados mientras el cron falla.
- `impact:other`: El impacto concreto es pérdida de frescura de la caché de categorías y ruido operativo que puede ocultar fallos reales.

## Summary

La incidencia sigue siendo necesaria: `dev` conserva el umbral obsoleto y una PR abierta ya propone la corrección, por lo que no debe cerrarse ni duplicarse antes del merge.

## What This Changes

Sustituir los mínimos de categorías distintas por mínimos de asignaciones para evitar falsos positivos del cron sin permitir escrituras de Redis desde una fuente parcial.

## Best Possible Solution

Integrar una validación por volumen de asignaciones con errores `actual/floor`, manteniendo el rechazo previo a Redis y comprobando después una ejecución completa y otra con entrada parcial.
