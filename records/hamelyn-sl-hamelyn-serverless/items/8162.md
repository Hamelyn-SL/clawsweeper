## Summary

Gracias por el contexto: `dev` mantiene una ruta que colapsa candidatos por EAN y prioriza `stock.asin`, así que el problema sigue vigente. No hay una PR enlazada; antes de implementar hace falta decidir el modo regional y el rollout.

## What This Changes

La issue solicita que Amazon resuelva y use una identidad ASIN/product type por `(EAN, marketplace)` sin reutilizar cachés globales entre regiones.

## Best Possible Solution

Introducir una identidad regional tipada y única por EAN/marketplace, mantener los escalares legacy fuera del write path Amazon y activar primero `shadow` en FR antes de evaluar `enforce` o cualquier backfill.
