## Summary

La incidencia sigue siendo necesaria: `dev` solo filtra el reintento de Slack y un caso de ASIN, mientras que varias firmas benignas descritas aún pasan al watcher. El PR abierto de lock cubre únicamente una parte del ruido.

## What This Changes

Ampliar las firmas esperadas del watcher de marketplace, evitar consultar avisos con desenlace correcto y exigir repetición para señales catastróficas recuperables.

## Best Possible Solution

Definir una política por desenlace: bajar a `info` y excluir solo señales con recuperación o estado final verificable; mantener el escalado de errores sin confirmación y reutilizar la lógica acotada del PR de lock cuando se apruebe.
