## Label Justifications

- `P2`: El ruido del watcher consume triage y puede ocultar señales de marketplace, pero no acredita una interrupción inmediata del servicio.
- `impact:other`: El efecto concreto es observabilidad operativa defectuosa: incidencias benignas compiten con alertas accionables.

## Summary

Gracias por el contexto: el watcher actual todavía deja pasar las firmas descritas y permite que cualquier timeout aislado salte el umbral. La incidencia sigue siendo necesaria, pero la ampliación global de la excepción requiere una decisión explícita de política de alertas.

## What This Changes

Ampliar el filtrado de firmas benignas del `marketplace-errors-watcher`, corregir los niveles de log en origen y revisar cuándo un timeout debe abrir una incidencia sin recurrencia.

## Best Possible Solution

Definir una taxonomía de desenlaces recuperados o esperados, filtrar solo esas firmas con pruebas y mantener una excepción de recurrencia limitada para los timeouts que el equipo acuerde.

Options:

- **Clasificar por causa y desenlace (recommended):** Mantener alerta inmediata para timeouts no recuperados y exigir recurrencia solo para causas transitorias demostradas, empezando por el lock Mongo.
- **Exigir recurrencia para todo timeout:** Reducir el ruido aplicando dos requests en quince minutos a cualquier timeout de marketplace, aceptando una detección más tardía.
- **Conservar el escalado actual:** Aplicar únicamente firmas benignas inequívocas y dejar todos los timeouts aislados como catastróficos.

## Reproduction Assessment

Sí, desde código: cualquier mensaje con `timed out` evita el umbral, y las firmas propuestas no coinciden con las dos exclusiones actuales. La benignidad de cada muestra concreta requiere contrastar sus desenlaces operativos.

## Solution Assessment

No del todo: ampliar exclusiones específicas es la vía mantenible, pero aplicar un umbral único a todos los timeouts contradice el alcance deliberadamente limitado de https://github.com/Hamelyn-SL/hamelyn-serverless/pull/9308.
