## Summary

El cambio corrige la lectura de ambos formatos de `order` sin alterar la conversión histórica; queda por confirmar y autorizar el relleno masivo de las filas históricas antes de considerar resuelto el impacto completo.

## What This Changes

El PR hace que `stocks-materialize.sql` lea `orderId` desde un hexadecimal plano y mantenga el fallback para la estructura histórica `{timestamp, nonce}`.

## Best Possible Solution

Mantener el `COALESCE` y ejecutar, con autorización explícita, un backfill acotado y verificado desde `mongodb.stocks` después de desplegar el cambio.
