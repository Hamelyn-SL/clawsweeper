## Summary

La corrección aborda el caso central descrito en la issue vinculada: consulta Amazon tras el rechazo concreto y solo acepta el estado `SHIPPED` del mismo pedido. Mantendría el PR abierto para que el equipo valore el riesgo reconocido de tracking distinto y decida si hace falta una comprobación adicional antes de persistirlo.

## What This Changes

El adaptador de envíos de Amazon consulta `getOrder` tras `PackageToUpdateNotFound` y devuelve `SHIPPED` solo si coincide el pedido y el estado remoto es `SHIPPED`, con pruebas y documentación del comportamiento.

## Best Possible Solution

Conservar la consulta remota acotada y el fallback a `SYNC_ERROR` para estados no confirmados; antes de integrar, acordar si el tracking debe coincidir para aceptar `SHIPPED` o si el estado de Amazon basta como verdad del pedido.
