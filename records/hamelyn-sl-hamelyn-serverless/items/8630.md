## Summary

El PR aporta una migración amplia y bien trabajada, pero el switchover programado deja sin ejecución automática dos fases legacy necesarias: `update` para `needsUpdateData` y `recover` para errores V1. Debe mantenerse abierto y no fusionarse hasta preservar esos flujos o aplazar el cambio de schedule con aprobación explícita.

## What This Changes

El PR incorpora `MarketplaceManager` V2 para Discogs, sus runners y adaptador, y mueve el cron principal de `/api/discogs` a `/api/discogsV2`.

## Best Possible Solution

Mantener el cron V1 programado hasta que V2 ejecute `needsUpdateData` y migre o cubra los errores legacy; después, activar V2 con índices Atlas verificados y evidencia real redactada.
