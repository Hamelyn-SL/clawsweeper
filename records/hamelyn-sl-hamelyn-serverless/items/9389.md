## Label Justifications

- `impact:auth-provider`: El problema depende del contrato de autenticación entre Actions de Auth0 y el endpoint administrativo protegido por token.

## Summary

Gracias por el contexto: el fallo sigue siendo necesario de resolver. El código actual exige el token y el snapshot no lo envía; falta una decisión de producto sobre mantener el aprovisionamiento sin login antes de tocar el tenant.

## What This Changes

La incidencia propone corregir o retirar dos Actions de Auth0 sin token y versionar su configuración para evitar divergencias del tenant.

## Best Possible Solution

Conservar el aprovisionamiento en `post-user-registration` si se confirma que las altas sin login deben crear usuario, y desplegar Actions versionadas con sus secrets y una validación de alta sin login.
