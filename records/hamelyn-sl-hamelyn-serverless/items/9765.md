## Label Justifications

- `P1`: Los agentes de revisión continúan ejecutándose y publicando señales no fiables mientras la cuota permanece agotada.
- `impact:other`: El impacto concreto es la fiabilidad operativa de automatizaciones internas de revisión, fuera de las categorías específicas disponibles.

## Summary

La incidencia sigue vigente: `dev` reintenta los 429 sin distinguir cuota agotada y varias rutas aún convierten ese caso en un fallo publicable. El PR de telemetría relacionado no implementa este skip y lo declara expresamente fuera de alcance.

## What This Changes

Añadir un corte explícito por cuota Codex agotada para Asamblea, Proof y Skill Guardian, evitando reintentos y resultados que aparenten una revisión fallida.

## Best Possible Solution

Acordar primero el alcance del gate y después propagar un resultado tipado de cuota agotada por HTTP, CLI y workflow, conservando los reintentos para 429 realmente transitorios.

## Maintainer Decision

Question: ¿La primera entrega debe limitarse al corte local tras el primer `usage_limit_reached`, o debe incluir estado compartido para evitar incluso esa primera llamada en nuevas instancias?

Rationale: La memoria por proceso del PR de telemetría no resuelve el comportamiento entre lambdas; elegir persistencia compartida cambia infraestructura, coste y alcance del trabajo.

Likely owner: JavierHamelyn

Owner reason: Ha mantenido recientemente el cliente Codex y el PR de telemetría que define las limitaciones de estado por proceso.

Owner confidence: high

Options:

- **Corte local primero (recommended):** Detectar `usage_limit_reached`, detener el run actual y propagar un skip limpio; dejar el estado compartido como seguimiento separado.
- **Gate compartido ahora:** Persistir el reset de cuota para que nuevas instancias hagan skip antes de llamar a Codex, asumiendo diseño y operación adicionales.

## Reproduction Assessment

No se ha ejecutado una cuota agotada en esta revisión, pero el recorrido es reproducible desde código: un 429 entra en los reintentos HTTP y estructurados, y el CLI de Asamblea también queda marcado como reintentable.

## Solution Assessment

No; cambiar solo el clasificador HTTP dejaría activos los reintentos inmediatos estructurados, la ruta CLI de Asamblea y el contrato de Skill Guardian.
