## Summary

El enfoque elimina correctamente el salto interno, pero el `catch` del proxy convierte una caída transitoria del JWKS en 401 y expone el mensaje bruto de `jose`; es un bloque P1 ya señalado en la revisión humana.

## What This Changes

El PR valida JWT y audiencia en el proxy de Data Dashboards, elimina `/api/auth/authorize` y aplica la autorización de roles mediante un wrapper en cada ruta API.

## Best Possible Solution

Distinguir credenciales inválidas de errores transitorios al consultar JWKS: devolver un 503 con mensaje fijo, registrar el detalle en servidor y añadir una regresión para esa indisponibilidad.
