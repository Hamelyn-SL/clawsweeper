## Label Justifications

- `P1`: La combinación de JWT válido sin comprobación de roles puede abrir datos internos de analítica a usuarios no autorizados.
- `merge-risk: 🚨 security-boundary`: El cambio desplaza el control de roles desde el proxy a wrappers de ruta y una ruta nueva queda fuera de ese perímetro.
- `merge-risk: 🚨 auth-provider`: El proxy pasa a decidir qué bearer puede llegar al mecanismo que valida JWT, roles y credenciales de Data Dashboards.

## Summary

Este PR sigue siendo necesario para eliminar la invocación extra, pero no es fusionable aún: al actualizarlo con `dev`, dejaría una ruta nueva de analítica sin la comprobación de roles.

## What This Changes

El PR sustituye el `fetch` interno de autorización del proxy por validación local de JWT y envuelve las rutas de Data Dashboards para resolver roles en la misma invocación.

## Best Possible Solution

Rebasar sobre `dev`, envolver todas las rutas de datos actuales —incluida `agent-memory`— y conservar un proxy que derive JWT y futuras credenciales admitidas hacia la autorización específica de ruta.
