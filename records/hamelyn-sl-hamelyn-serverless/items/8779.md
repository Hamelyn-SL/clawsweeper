## Summary

El fallo central ya está corregido en `dev` y fue desplegado a producción: el schedule usa el dispatcher HTTP y no invoca `receive()` sobre Eve. La comprobación end-to-end pendiente depende del gate distinto de https://github.com/Hamelyn-SL/hamelyn-serverless/issues/9013.

## What This Changes

La incidencia pedía sustituir el despacho programado mediante `receive(eve, ...)` por el dispatcher HTTP ya usado por la ruta manual.

## Best Possible Solution

Mantener el dispatcher HTTP actual y resolver la importación o semilla de baseline en https://github.com/Hamelyn-SL/hamelyn-serverless/issues/9013 para recuperar la validación end-to-end.

## Maintainer Decision

## Reproduction Assessment

No en `dev`: el código actual no contiene la llamada a `receive()` y los schedules delegan en HTTP. No se puede completar un tick con acciones porque el gate de baseline lo bloquea antes.

## Solution Assessment

Sí para este defecto: reutilizar el dispatcher HTTP autenticado de la ruta manual elimina la incompatibilidad del canal y mantiene un único mecanismo de entrega.
