## Summary

La concurrencia nueva entre `PICKING` y `OTROS` deja inoperativo el flujo `NE-`: el cliente envía la sesión de Picking, pero el servidor exige una sesión `OTROS` para esa OP. La issue enlazada sigue abierta y este PR continúa siendo su candidata de implementación.

## What This Changes

El PR agrupa Buscalibre, Fusionado e inventarios en una única sesión `OTROS` con detalle, añade su panel administrativo y adapta telemetría, conteos, contrato OpenAPI y documentación.

## Best Possible Solution

Mantener una única sesión `OTROS` como dirección acordada, pero seleccionar explícitamente su `sessionId` para las OP `NE-` y cubrir la coexistencia con Picking mediante una regresión focalizada.
