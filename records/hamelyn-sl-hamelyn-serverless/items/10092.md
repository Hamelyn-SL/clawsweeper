## Summary

La ruta descrita sigue presente: la fusión y el trasvase cambian la cubeta sin limpiar `withdrawalReason`, mientras que la reactivación depende de que el webhook detecte una cubeta previamente bloqueada. No hay una PR abierta conocida que cubra este caso.

## What This Changes

Solicita reactivar los stocks `BIN_BLOCKED` cuando se trasladan a una cubeta sana, o aplicar un estado coherente al destino, con cobertura para la fusión.

## Best Possible Solution

Definir una regla única para traslados de stocks bloqueados: si el destino está sano, reactivar y sincronizar los marketplaces; si no puede verificarse su estado, conservar el bloqueo. Cubrir fusión y trasvase con pruebas.
