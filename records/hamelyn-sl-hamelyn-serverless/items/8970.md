## Summary

La incidencia sigue siendo necesaria: el código actual convierte cualquier `issues.length > 0` de PUT/PATCH en excepción, aunque Amazon devuelva `ACCEPTED` con WARNING/INFO; además, el normalizador sigue perdiendo el código del issue.

## What This Changes

Corregir el alta Amazon V2 para aceptar respuestas ACCEPTED con issues WARNING/INFO, comprobar buyability cuando se ignore `purchasable_offer` y normalizar el código desde los issues.

## Best Possible Solution

Separar issues bloqueantes de avisos aceptados en PUT/PATCH; para el warning de `purchasable_offer`, confirmar buyability antes de completar el alta y conservar el código Amazon específico en el resultado de error.

Sí, por código: una respuesta PUT o PATCH `ACCEPTED` con un issue WARNING entra hoy en la condición de excepción. La observación en vivo aportada confirma que esa ruta llega al cron V2.

## Solution Assessment

Sí, con un matiz: filtrar por severidad es el arreglo mínimo, pero el warning de oferta debe pasar por la verificación de buyability existente antes de declararlo éxito.

## Repair Work Prompt

Corrige la clasificación de respuestas Amazon Listings V2 para que PUT/PATCH solo lancen con `status === "INVALID"` o con al menos un issue `severity === "ERROR"`. Para WARNING/INFO aceptados, conserva el flujo; si el warning indica que `purchasable_offer` fue ignorado, ejecuta la verificación de buyability y devuelve un error clasificado si no queda BUYABLE con cantidad positiva. Actualiza `normalizeAmazonError` para derivar el código desde `getAmazonListingIssues` antes del fallback `AMAZON_NETWORK`. Añade pruebas focalizadas para WARNING ACCEPTED, ERROR/INVALID y normalización. No cambies contratos V2 ajenos ni el retry general. Relación: https://github.com/Hamelyn-SL/hamelyn-serverless/issues/8685. Incluye evidencia de ejecución real o logs redactados de SP-API en la futura PR; no edites `CHANGELOG.md`.
