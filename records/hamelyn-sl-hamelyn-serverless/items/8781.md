## Summary

El problema sigue siendo necesario: el código actual permite reactivar un pedido cancelado como `PICKED_UP`, lo devuelve a la cola y no excluye el rechazo terminal de AbeBooks del recovery. Hace falta una decisión conjunta de Marketplace y Almacén antes de fijar la guarda definitiva.

## What This Changes

La incidencia solicita impedir reactivaciones inseguras de pedidos cancelados, dimensionar la confirmación de AbeBooks y propagar los fallos de envío del cron.

## Best Possible Solution

Definir una política explícita de recogida tardía y aplicar una guarda server-side; después clasificar el rechazo de AbeBooks, ajustar el batch con presupuesto verificado y hacer que el cron comunique fallos accionables.
