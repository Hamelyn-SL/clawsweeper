## Summary

El cambio refuerza la validación de los hallazgos cuando se aportan sus datos, pero la propia herramienta deja pasar sin gate una llamada de heartbeat que omita ambos campos. Eso mantiene un camino directo para crear issues sin verificar los dos ciclos.

## What This Changes

El PR añade validación en `create_github_issue` para contrastar findings de heartbeat y su efecto esperado con el ledger antes de crear una issue.

## Best Possible Solution

La herramienta debería poder reconocer de forma fiable una llamada procedente de heartbeat y exigir allí el ledger y el efecto medible, manteniendo el flujo sin esos campos para solicitudes humanas y otros usos legítimos.
