## Summary

El parche aborda una carrera real, pero puede marcar una recepción como completada sin enviar `RECEPTION_CONFIRM`; debe corregirse antes de integrar.

## What This Changes

El PR convierte el lease de recepción en un fencing token y lo consume antes de notificar para evitar correos duplicados tras un relevo.

## Best Possible Solution

Persistir una marca idempotente de notificación u outbox vinculada a la transición exitosa, en vez de inferir el resultado desde un lease efímero ya liberado.
