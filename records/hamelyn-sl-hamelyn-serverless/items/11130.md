## Summary

Gracias por el contexto: el catálogo ya contiene los cinco motivos, pero la cancelación web sigue enviando únicamente el identificador del pedido y la API conserva el motivo genérico. La decisión previa del equipo sobre si la selección debe ser obligatoria sigue pendiente; la captura aún no está implementada.

## What This Changes

Añadir a la cancelación web una selección de los cinco motivos de cliente existentes y guardar en el pedido el motivo elegido.

## Best Possible Solution

Ampliar los flujos web autenticado y de invitado para recoger y persistir el motivo del catálogo compartido, manteniendo coherentes las rutas de API y la visualización posterior del pedido.

Rationale: El comportamiento solicitado no define qué hacer si el cliente no responde; exigir una selección o permitir omitirla cambia el flujo y el dato persistido, y el comentario previo dejó expresamente esa elección al equipo.

Options:

- **Exigir selección (recommended):** Solicitar uno de los cinco motivos antes de confirmar la cancelación web.
- **Permitir omitir:** Guardar el motivo elegido cuando exista y conservar el respaldo actual si se omite.
- **Mantener el flujo actual:** No añadir la captura de motivos al proceso de cancelación web.

## Solution Assessment
