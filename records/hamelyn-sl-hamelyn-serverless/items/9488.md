## Summary

La incidencia sigue siendo necesaria: el merge actual actualiza las cajas internas, pero no sincroniza una recogida MRW que ya tiene tracking. Hace falta decidir y validar con MRW el circuito seguro antes de implementar.

## What This Changes

La incidencia pide que las cajas resultantes de fusionar lotes se sincronicen con MRW cuando la recogida ya está contratada.

## Best Possible Solution

Definir con Operaciones el comportamiento ante un aumento de cajas con tracking y, si MRW lo admite, implementar una actualización idempotente con confirmación y cobertura del caso 2→5.

Rationale: La integración tiene soporte de modificación, pero no existe un flujo aplicado al merge ni evidencia de qué operación acepta MRW para una recogida contratada.

Likely owner: JavierHamelyn

Owner confidence: high

Options:

- **Modificar mediante MRW (recommended):** Añadir una actualización idempotente de bultos solo tras validar el endpoint, la aceptación y la respuesta operativa de MRW.
- **Cancelar y recrear:** Usar cancelación y nueva recogida únicamente si Operaciones confirma que no duplica ni pierde la planificación existente.
- **Bloquear la fusión posterior:** Impedir aumentos de cajas cuando exista tracking hasta disponer de un circuito externo validado.

No hay una reproducción ejecutada contra `dev`, pero el código confirma que el merge guarda las cajas sin llamar al transportista. El caso 795BB aporta una secuencia operativa compatible con ese hueco.

## Solution Assessment

No; implementar una llamada automática sin acordar el contrato de modificación de MRW sería arriesgado. La vía adecuada es definir primero la operación permitida y su confirmación.
