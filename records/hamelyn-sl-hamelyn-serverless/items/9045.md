## Summary

Mantengo esta incidencia abierta como informe canónico: el cron actual aísla cada fallo, pero el rechazo HTTP 400 de Fnac sigue apareciendo en pedidos distintos y aún no tiene una clasificación segura.

## What This Changes

Investigar y resolver los rechazos HTTP 400 al confirmar envíos Fnac desde `/api/fnacV2`.

## Best Possible Solution

Identificar el código funcional completo de Fnac y clasificar únicamente esa respuesta terminal, con cobertura de éxito, rechazo permanente y error recuperable.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Debe un HTTP 400 de Fnac que devuelve `state: shipped` y estado `fatal` marcarse como envío confirmado, como rechazo terminal, o mantenerse como `SYNC_ERROR` recuperable?

Rationale: El código actual conserva el rechazo deliberadamente sin clasificarlo; elegir su estado interno afecta a la reconciliación de ventas y no puede deducirse con seguridad del fragmento de respuesta disponible.

Likely owner: JavierHamelyn

Owner reason: Su trabajo reciente abarca la configuración y el adaptador Fnac donde debe validarse la semántica del proveedor.

Owner confidence: high

Options:

- **Confirmar la semántica con Fnac (recommended):** Revisar el motivo completo o la documentación del proveedor y aplicar una clasificación explícita solo para esa firma terminal.
- **Mantener `SYNC_ERROR` temporalmente:** Conservar el comportamiento actual hasta disponer del motivo funcional completo, evitando convertir rechazos reales en envíos confirmados.
- **Tratarlo como confirmado:** Marcarlo como enviado solo si Fnac confirma que esa combinación de estado representa una aceptación idempotente.

## Reproduction Assessment

No hay una reproducción local de alta confianza sin una respuesta real de Fnac, pero la ruta actual y el log del watcher delimitan con precisión el camino que produce el `SYNC_ERROR`.

## Solution Assessment

No todavía: aislar el fallo evita bloquear otros pedidos, pero resolver esta incidencia exige clasificar la firma exacta de Fnac sin suponer que todo 400 es terminal.
