## Summary

Mantener abierta: `dev` todavía convierte cualquier `404` del DELETE de V2 en `gone`, y el runner lo consolida como retirada correcta. El antecedente fusionado corrigió el flujo heredado, no esta ruta V2; la confirmación remota propuesta exige decidir una política segura ante lecturas ambiguas.

## What This Changes

Evitar que la retirada V2 de TodoColección cierre como `gone` un `404` de DELETE sin confirmar que el anuncio remoto ya no existe.

## Best Possible Solution

Conservar como terminales solo respuestas semánticamente verificadas; ante un `404` genérico, validar de forma fiable la identidad remota y, si queda indeterminada, persistir un error reintentable sin tombstone.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Qué política debe seguir V2 cuando un DELETE devuelve `404` genérico: reintentar solo tras una identidad remota verificable o conservar siempre el listing para reintento hasta disponer de una confirmación fiable?

Rationale: La lectura del proveedor tiene antecedentes de `404` para listings activos y el reintento puede recorrer recuperación de referencias ambiguas; elegir la señal terminal cambia qué ventas se cierran o se retrasan.

Likely owner: Miguel Angel Hernández Perdomo

Owner reason: Su refactor aisló la capa V2 afectada; la decisión debe coordinarse con el precedente de `banosdavidhamelyn`.

Owner confidence: medium

Options:

- **Cerrar solo con evidencia semántica (recommended):** Mantener `gone` únicamente para claves API conocidas y dejar cualquier `404` genérico como error reintentable hasta validar una identidad remota fiable.
- **Reintentar por SKU validado:** Recuperar un ID por SKU y reintentar una vez solo cuando el proveedor confirme que corresponde al listing esperado y no entra en recuperación ambigua.
- **Conservar la reconciliación amplia:** Aceptar cualquier `404` como retirada ya realizada, asumiendo el riesgo actual de listings remotos aún comprables.

## Reproduction Assessment

Sí, por inspección de `dev`: un `404` del DELETE alcanza `isNotFound` y produce `gone`, que el runner persiste como retirada. La frecuencia e impacto exactos requieren los datos operativos aportados.

## Solution Assessment

No todavía: la dirección es correcta, pero usar `findRemoteProductId` como confirmación requiere validar el contrato de lectura y limitar la recuperación de referencias ambiguas.
