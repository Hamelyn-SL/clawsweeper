## Summary

La incidencia sigue siendo necesaria: el adaptador V2 convierte cualquier `404` de DELETE en `gone`, y el runner lo consolida como retirada aunque el identificador remoto pueda estar desfasado.

## What This Changes

Evitar que TodoColección cierre una retirada como `gone` tras un `404` de DELETE sin confirmar que el anuncio remoto realmente ha desaparecido.

## Best Possible Solution

Tras un DELETE `404`, resolver el anuncio por SKU: si existe, reintentar contra su id real; solo devolver `gone` cuando la ausencia remota quede confirmada y registrar los casos indeterminados como error reintentable.

Sí, a nivel de fuente: un DELETE que devuelve `404` pasa directamente a `gone` y el runner lo tombstonea. Los registros operativos aportados son coherentes con esa ruta, aunque esta revisión no ejecutó la API externa.

## Solution Assessment

Sí, con el matiz de reintentar contra el id devuelto por la búsqueda: reutiliza la capacidad ya expuesta, evita aceptar una señal negativa como prueba y conserva los errores para reintento.
