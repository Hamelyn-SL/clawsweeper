- `impact:other`: Las solicitudes operativas de cubeta a Astar pueden omitirse sin que Admin comunique el fallo.

## Summary

La incidencia sigue siendo necesaria: `dev` crea la NE-EX y depende de una relectura posterior para despacharla, por lo que una réplica atrasada puede devolver una lista vacía y cerrar el flujo sin pedir cubetas.

## What This Changes

Corregir GENERAR NE/S para que las NE-EX recién creadas soliciten sus cubetas aunque una réplica secundaria todavía no refleje la escritura.

## Best Possible Solution

Despachar también las revisiones recién creadas, leer del primario las pendientes existentes y definir una comprobación idempotente en Astar que convierta los pendientes persistentes en `NE_DISPATCH_PENDING`.
