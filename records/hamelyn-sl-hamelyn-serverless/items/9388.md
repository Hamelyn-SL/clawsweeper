## Label Justifications

- `P1`: La vía descrita podría permitir que usuarios autenticados del admin usen el resolver sobre assets privados, aunque falta confirmar el alcance efectivo del token de producción.
- `impact:security`: El asunto trata de autorización y posible acceso a datos privados mediante una credencial de GitHub.

## Summary

Gracias por el contexto: el código actual aún permite que una URL arbitraria entre en el cuerpo que después autoriza su resolución; los comentarios confirman además rutas por `name` multilínea y Markdown. El alcance real del token de producción sigue sin verificarse, así que el riesgo de acceso entre repositorios no está demostrado en producción.

## What This Changes

Exigir procedencia válida para los assets de GitHub nuevos que se guardan en issues, conservando los adjuntos existentes de la misma issue.

## Best Possible Solution

Validar los assets reconocidos en el cuerpo final antes de persistirlo, aceptando tickets válidos para URLs nuevas y conservando solo las URLs que ya pertenecen a esa issue; verificar por separado el alcance mínimo del token.
