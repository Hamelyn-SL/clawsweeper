## Label Justifications

- `P0`: Existe un bypass de autorización: un usuario autenticado puede introducir una URL y hacer que el servidor la resuelva con su token de GitHub.
- `impact:security`: El recorrido puede exponer assets privados de repositorios a los que alcance `GITHUB_ISSUES_TOKEN`.

## Summary

La incidencia sigue siendo necesaria: `dev` acepta URLs nuevas de assets de GitHub sin ticket y el resolver confía después en que aparezcan en la issue.

## What This Changes

Exigir un ticket HMAC para cada asset de GitHub nuevo al crear o editar una issue del admin, manteniendo los adjuntos que ya pertenecían a ella.

## Best Possible Solution

Validar en servidor todos los assets de GitHub del cuerpo final: exigir ticket para los nuevos, permitir solo los ya presentes en la misma issue y cubrir creación, edición y Markdown.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, por inspección de código: creación y edición aceptan URLs válidas sin ticket, y el resolver acepta después la presencia de esa URL en la issue.

## Solution Assessment

Sí, la vía más acotada es validar las URLs de GitHub al persistir el cuerpo final, comparándolas con los adjuntos preexistentes de la misma issue.
