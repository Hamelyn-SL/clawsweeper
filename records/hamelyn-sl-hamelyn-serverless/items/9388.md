## Label Justifications

- `P0`: El endpoint puede convertirse en proxy autenticado hacia adjuntos privados de otros repositorios alcanzables por el token.
- `impact:security`: El reporte describe una comprobación de procedencia insuficiente alrededor de un token con acceso a GitHub.

## Summary

La incidencia sigue siendo necesaria: `dev` permite persistir assets de GitHub nuevos sin acreditar la subida y el resolver después los acepta al encontrarlos en la issue.

## What This Changes

Exigir tickets HMAC para assets de GitHub nuevos al crear o editar issues, conservando los adjuntos preexistentes legítimos.

## Best Possible Solution

Validar cada asset de GitHub nuevo, incluido el extraído del Markdown, contra un ticket ligado a su URL; permitir solo los ya existentes en la misma issue y limitar el token al repositorio objetivo.

## Maintainer Decision

Required: false

## Reproduction Assessment

## Solution Assessment

Sí. Reutilizar la verificación HMAC existente al persistir URLs nuevas cierra la entrada que hace válido el fallback, sin romper adjuntos ya guardados.
