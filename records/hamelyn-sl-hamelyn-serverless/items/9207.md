## Summary

La incidencia sigue siendo necesaria: `dev` detecta el alvéolo activo, pero el OK confirma siempre `1_1_RIGHT`. La discusión posterior confirma que debe decidirse primero el contrato operativo con Exotec.

## What This Changes

Hacer que el OK de Station confirme la preparación del alvéolo activo o garantizar que Exotec sirva siempre por el alvéolo 1.

## Best Possible Solution

Cerrar con Exotec la garantía de `Alveolus_1_1_RIGHT` y validarla tras una OP con `NOT_FOUND`; si no es viable, ampliar el protocolo para confirmar explícitamente el alvéolo activo con contrato OPC UA verificado.

Sí, desde código: al recibir una preparación de `Alveolus_1_2_RIGHT` o superior, el bridge conserva ese nombre pero el OK sigue invocando el método fijo de `1_1_RIGHT`. Falta una ejecución OPC UA controlada para reproducirlo en vivo.

## Solution Assessment

No todavía. Adaptar el bridge es viable, pero no es la solución más segura hasta que Exotec confirme si puede garantizar el alvéolo 1 y, si no, los métodos de ACK de los alvéolos alternativos.
