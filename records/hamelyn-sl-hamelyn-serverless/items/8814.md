## Summary

El PR no corrige el transfer config vivo: `bq update --target_dataset=` entrega una cadena vacía que el cliente de BigQuery ignora, por lo que `mongodata` permanece configurado y el bloqueo de sitemaps continúa.

## What This Changes

El PR cambia la scheduled query SEO para declarar `targetDataset` vacío y hace que el script de despliegue emita `--target_dataset=` al actualizarla.

## Best Possible Solution

Usar una operación de BigQuery Data Transfer que realmente incluya la limpieza de `destinationDatasetId` en el update mask, y demostrar después un `show` del config y un transfer run satisfactorio.
