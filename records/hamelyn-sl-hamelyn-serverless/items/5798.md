## Label Justifications

- `P1`: El cron de producción se ejecuta cada tres minutos y su timeout puede retrasar repetidamente el procesamiento de notificaciones Amazon.
- `impact:crash-loop`: La firma observada es el agotamiento terminal del runtime de Vercel en esta ruta.

## Summary

Mantener abierta: el controlador vigente reserva tiempo antes del siguiente lote, pero no antes de cada mensaje ya recibido; un `ORDER_CHANGE` lento puede seguir agotar el runtime antes del borrado SQS.

## What This Changes

Evitar que `/api/amazon-notifications-pull` alcance los 150 segundos de Vercel al procesar varios mensajes lentos dentro de un lote SQS.

## Best Possible Solution

Añadir un guard conservador antes de cada mensaje, retener los pendientes como `execution_budget`, borrar los completados y cubrir ambos resultados con una prueba de regresión.

## Solution Assessment
