## Label Justifications

- `P1`: El cron programado cada tres minutos puede retrasar repetidamente el procesamiento operativo de notificaciones Amazon.
- `impact:crash-loop`: La firma observada agota el runtime de la función y termina la ejecución con un 504.

## Summary

Mantener abierta: el código actual reserva tiempo antes de recibir otro lote, pero no entre los mensajes ya recibidos; un lote lento aún puede agotar los 150 segundos antes del borrado SQS.

## What This Changes

Evitar que `/api/amazon-notifications-pull` alcance el límite de 150 segundos de Vercel mientras procesa notificaciones Amazon.

## Best Possible Solution

Añadir un guard antes de cada mensaje que retenga los pendientes como `execution_budget`, borre los ya completados y deje la recuperación al siguiente run.

## Repair Work Prompt

Corrige el timeout de `/api/amazon-notifications-pull` incorporando un control de `executionBudgetMs` antes de cada mensaje recibido. Cuando no quede margen, marca los pendientes como `execution_budget`, no los borres y ejecuta el borrado batch de los completados. Conserva la semántica de SQS, no cambies las rutas de stock inexistente ni `getOrder`, y no añadas scripts one-time al PR. Relacionados: https://github.com/Hamelyn-SL/hamelyn-serverless/issues/5798 y https://github.com/Hamelyn-SL/hamelyn-serverless/pull/5799.
