- `impact:other`: El problema puede atascar una operación logística de almacén y no encaja directamente en las categorías de impacto más específicas.

## Summary

Gracias por el reporte y la reproducción documentada: el fallo sigue siendo posible en `dev`. La planificación no reserva las líneas antes de enviar BringBins y el rollback puede cancelar una petición compartida, dejando la NE sin cubeta.

## What This Changes

Dos generaciones simultáneas de una NE-EX para el mismo OP pueden provocar que el rollback de una llamada cancele una petición BringBins necesaria para la otra.

## Best Possible Solution

Hacer que generaciones concurrentes del mismo OP no compartan la operación BringBins y que cada rollback solo pueda cancelar líneas identificadas como propias; cubrir ambos casos con pruebas de concurrencia y compensación.

Required: false

## Reproduction Assessment

Sí, hay un camino de reproducción concreto respaldado por el caso real y la simulación documentada: dos generaciones del mismo OP comparten una instrucción y el rollback de una cancela la línea viva. El código actual conserva esa selección y cancelación por instrucción.

## Solution Assessment

No consta una solución aplicada. La dirección más segura combina exclusión de generaciones simultáneas con cancelación limitada a líneas atribuibles a la invocación, verificando reintentos y fallos parciales.
