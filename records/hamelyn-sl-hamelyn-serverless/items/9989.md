## Summary

La épica sigue siendo necesaria: el código conserva adaptadores y envíos directos, pero no implementa aún una entrada central, un dispatcher ni la topología validada de workers.

## What This Changes

Centralizar gradualmente los emails existentes mediante una API de notificación, configuración de eventos, cola y workers, dejando la trazabilidad persistente y los estados externos para fases posteriores.

## Best Possible Solution

Completar primero el inventario de flujos y conservar sus marcas y contratos; después validar en no producción una topología de cola antes de migrar cada familia de emails.
