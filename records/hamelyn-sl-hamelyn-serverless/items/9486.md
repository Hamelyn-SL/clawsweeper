## Summary

La mejora sigue siendo necesaria: `dev` aún genera la cabecera Markdown de cinco líneas y sus consumidores leen ese formato, sin un marcador HTML de metadata ni presentación compacta.

## What This Changes

La issue propone guardar los cinco metadatos de wishlist en un marcador HTML y mostrar una cabecera compacta, conservando la lectura del formato heredado y haciendo backfill.

## Best Possible Solution

Introducir un contrato de metadata versionado que priorice el marcador HTML, conserve el parser heredado y migre las wishlists existentes solo tras desplegar lectores compatibles.
