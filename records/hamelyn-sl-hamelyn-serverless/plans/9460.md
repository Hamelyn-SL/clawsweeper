# Coding Plan for hamelyn-sl/hamelyn-serverless#9460: TodoColección: la retirada cierra como gone cualquier 404 del DELETE y el anuncio se revende al cliente

Source report: [records/hamelyn-sl-hamelyn-serverless/items/9460.md](records/hamelyn-sl-hamelyn-serverless/items/9460.md)

## Summary

La incidencia sigue siendo necesaria: el adaptador V2 convierte cualquier `404` de DELETE en `gone`, y el runner lo consolida como retirada aunque el identificador remoto pueda estar desfasado.

## Plan

Corrige la retirada V2 de TodoColección para que un DELETE `404` no produzca `gone` sin confirmar el estado remoto. Tras el fallo, busca por SKU con `findRemoteProductId`; si hay un id remoto, reintenta el DELETE contra ese id; si no existe, devuelve `gone`; si la consulta o el nuevo DELETE son indeterminados, devuelve un error reintentable con diagnóstico útil. Añade regresiones para id almacenado obsoleto, ausencia confirmada y fallo de consulta. No cambies la semántica de `administrative_issues`, otros marketplaces ni `CHANGELOG.md`. Contexto: https://github.com/Hamelyn-SL/hamelyn-serverless/issues/8642 y https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7045.
