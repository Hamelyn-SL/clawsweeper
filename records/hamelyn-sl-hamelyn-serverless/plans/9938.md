## Summary

La concurrencia nueva entre `PICKING` y `OTROS` deja inoperativo el flujo `NE-`: el cliente envía la sesión de Picking, pero el servidor exige una sesión `OTROS` para esa OP. La issue enlazada sigue abierta y este PR continúa siendo su candidata de implementación.

## Plan

Corrige el flujo de OP `NE-` cuando el operario tiene `PICKING` y `OTROS` abiertos: la petición debe resolver y enviar el `sessionId` de `OTROS`, no el de Picking. Conserva la política de una única sesión `OTROS`, no cambies el backfill histórico ni la dirección funcional acordada en https://github.com/Hamelyn-SL/hamelyn-serverless/issues/9898. Añade una regresión focalizada para reclamar y resolver una línea `NE-` con ambas sesiones activas; ejecuta la prueba del workspace admin y las comprobaciones focalizadas aplicables.
