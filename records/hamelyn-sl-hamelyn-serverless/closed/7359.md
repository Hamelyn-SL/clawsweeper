## Summary

Mantener abierto: en `dev` el servidor ya calcula `shouldBypassStripe` con tolerancia de 1 céntimo, pero el checkout sigue decidiendo el bypass con `total <= 0` y no usa el flag que recibe del endpoint de cupones. No hay una PR abierta que cierre este bug; la PR BL relacionada solo documenta la divergencia y mantiene la regla de no cambiar comportamiento en el bloque BL.

## What This Changes

El issue pide que la UI de checkout use el `shouldBypassStripe` devuelto por el servidor para alinear el bypass de Stripe ante residuos de 0,01 €.

## Best Possible Solution

Hacer que `CheckoutContext` trate el flag servidor `couponResolution.shouldBypassStripe === true` como fuente de verdad para el bypass, conservando un fallback local seguro y cobertura dirigida del caso 0,01 €.

Sí, a nivel de fuente: el servidor devuelve `shouldBypassStripe` con tolerancia de 1 céntimo, mientras `CheckoutContext` usa `total <= 0` y por tanto un total de 0,01 no bypassa Stripe.

## Solution Assessment

Sí: consumir el flag servidor en el contexto de checkout es la solución más estrecha y mantiene una única fuente de verdad para la tolerancia ya aceptada en core.
