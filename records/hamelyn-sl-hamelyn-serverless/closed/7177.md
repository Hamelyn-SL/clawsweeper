## Summary

Mantener abierta: esta issue sigue siendo el tracking canónico de un fallo confirmado de sobreventa en Casa del Libro. `dev` ya previene parte de las nuevas activaciones tardías, pero todavía no descubre ni retira ofertas huérfanas sin fila `mk_casaDelLibro`, y las issues posteriores remiten aquí como duplicadas.

## What This Changes

Corregir el pipeline de Casa del Libro para que las ofertas Mirakl de stocks `WITHDRAWN` no permanezcan activas cuando falta su fila local del marketplace.

## Best Possible Solution

Añadir una reconciliación periódica de CDL que detecte por snapshot los SKUs huérfanos, confirme en la API viva cuáles siguen activos, rehidrate un documento mínimo `mk_casaDelLibro` y los entregue al withdraw normal; complementar esto con un backfill acotado y con una confirmación de batch que no borre la referencia local sin evidencia suficiente de retirada.

Likely owner: JavierHamelyn

Owner reason: Es la persona con trabajo fusionado más reciente en la prevención de listings vendidos y con historial directo en la API de Casa del Libro.

Owner confidence: medium

Options:

- **Snapshot más API viva (recommended):** Usar el snapshot para descubrir candidatos y verificar cada oferta en Mirakl antes de rehidratarla y retirarla, limitando falsos positivos y llamadas.
- **Rehidratar desde snapshot:** Crear filas mínimas para toda la cohorte del snapshot y dejar que el cron retire, aceptando que algunas entradas puedan estar obsoletas.
- **Barrido completo de Mirakl:** Construir la reconciliación desde la API como fuente principal, con mayor coste operativo y exposición a rate limits.

## Reproduction Assessment

Sí, a nivel de fuente y evidencia operacional: los snapshots y muestras de API viva documentan ofertas activas sin fila local, y `dev` confirma que tanto withdraw como recovery parten de documentos `mk_*` existentes. No se ejecutó una nueva consulta de producción durante esta revisión.

## Solution Assessment

No completamente: el guard fusionado del pipeline de upload es una prevención correcta, pero no repara el acumulado ni cubre ofertas huérfanas; la solución mantenible necesita reconciliación externa, backfill controlado y una política explícita de confirmación de batch.
