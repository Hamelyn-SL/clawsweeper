## Summary

El cambio sigue siendo necesario para https://github.com/Hamelyn-SL/hamelyn-serverless/issues/8728, pero el head actual puede dejar lotes sin cierre, informar cierres inexistentes y desincronizar una cubeta de Skypod.

## What This Changes

El PR crea stocks al escanear cada gaveta, encola su entrada en Skypod y cambia el cierre del lote para que solo compruebe stocks ya creados.

## Best Possible Solution

Conservar la validación por gaveta, pero hacer atómicas las precondiciones del producto, cargar el contenido físico completo del bin y ejecutar el trabajo pesado fuera de la petición del kiosko.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, desde código: escanear un código base Exotec con productos solo en `A` o `C` crea stocks pero no encuentra la orden para encolarla al cierre. También es reproducible con un bin compartido que supere el presupuesto HTTP.

## Solution Assessment

No: el reparto por gaveta es coherente, pero la implementación debe preservar el contenido completo de Skypod, distinguir encolado de cierre y no depender de un timeout interactivo.
