## Label Justifications

- `P0`: La autorización actual permite acceso o mutación de carritos mediante identificadores controlados por el cliente.
- `impact:security`: La issue corrige una frontera de autorización insuficiente con impacto directo de IDOR.

## Summary

Mantener abierta: `dev` sigue autorizando operaciones de carrito con identificadores aportados por el cliente y la PR vinculada permanece abierta, en borrador y asignada para resolver este límite de seguridad.

## What This Changes

La issue pide proteger el carrito web con capability en cookie para anónimos y JWT para usuarios, eliminando la confianza en `cartId` y `userId` del cliente.

## Best Possible Solution

Integrar un guard único para todas las rutas ecommerce, persistir solo el hash de la capability y validar el merge exclusivamente con JWT más la capability del carrito anónimo.

- **Ventana corta con corte explícito (recommended):** Mantener acceso legacy solo hasta una fecha cercana, instrumentar el uso y exigir capability después del corte.

## Reproduction Assessment

Sí, por inspección de `dev`: las rutas aceptan `cartId` y, en varios casos, `userId` del cliente sin una prueba centralizada de posesión. No se ejecutó una explotación contra un entorno real durante esta revisión.

## Solution Assessment

Sí, con la decisión pendiente sobre legacy: capability para anónimos, JWT para identidad autenticada y un guard común son el límite más mantenible para estas rutas.
