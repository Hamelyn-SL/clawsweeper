## Summary

La corrección sigue siendo necesaria en `dev` y el 409 propuesto es adecuado, pero el nuevo log incondicional duplicaría errores que `sales` y `profile` ya registran; además falta prueba real posterior al cambio.

## What This Changes

El PR devuelve HTTP 409 con `error: CART_USER_CONFLICT` cuando un carrito pertenece a otro usuario y registra los errores no-`BaseError` antes de responder 500.

## Best Possible Solution

Centralizar el logging de errores no controlados para emitir un único evento con contexto y `requestId`, mantener el 409 del carrito y aportar una ejecución real redactada antes del merge.

## Solution Assessment

No del todo. El 409 es la solución estrecha correcta, pero el logging debe conservar una sola fuente de verdad y evitar duplicar los eventos estructurados existentes.
