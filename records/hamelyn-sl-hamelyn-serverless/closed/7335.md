## Summary

Mantendría esta PR abierta: corrige el área adecuada para el fallo de incidencias eDesk vacías, pero aún falta prueba de comportamiento real posterior al cambio y el cambio de fallo parcial a `502` merece validación de upgrade/clientes antes de fusionar.

## What This Changes

La rama centraliza reintentos de `429` en el cliente eDesk, exige y envía `subject` en mensajes, y devuelve `502` con `ticketId` cuando el ticket se crea pero el mensaje falla.

## Best Possible Solution

Fusionar una vez que el revisor del área confirme la semántica fail-closed y el PR incluya prueba real redacted del retry/fallo parcial, manteniendo el retry en el cliente compartido para no duplicar lógica por endpoint.

## Solution Assessment

Sí, la frontera propuesta es la más mantenible: retry/backoff en el cliente compartido eDesk y fallo parcial propagado por el pipeline común. Lo que falta no es otro diseño, sino prueba real y confirmación de la semántica `502`.
