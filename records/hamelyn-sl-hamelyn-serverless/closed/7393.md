Mantener el enfoque de recálculo server-side, pero antes de mergear exigir que todas las fuentes confiables queden ligadas al carrito/usuario correcto y que las reglas de cupón, moneda y pedido gratuito tengan paridad probada con el storefront.

Full review comments:

- **[P1] Comprueba la propiedad del carrito antes de usar sus precios:** `apps/hamelyn-ecommerce/app/api/v5/checkout/route.ts:142-146`
  - body: El PR convierte el carrito persistido en fuente confiable, pero aquí carga cualquier `cartId` válido con `findCartEcommerce` antes de la comprobación de `resolveCheckoutCartId`. Un usuario que aporte un carrito ajeno o antiguo puede hacer que el servidor use esos precios para validar y persistir el checkout; la fuente confiable debe ser el carrito asignable al usuario/anónimo actual o, si no, caer a disponibilidad viva.
  - confidence: 0.9
- **[P2] Usa el mismo envío que el frontend para validar cupones:** `apps/hamelyn-ecommerce/app/api/v5/checkout/route.ts:641-648`
  - body: Para sitios no EUR, el frontend decide el envío gratis con importes ya convertidos y envía ese `netShippingCost` al endpoint admin de cupones. Este PR vuelve a calcular el descuento con `eurAmounts.shippingCost`, que puede conservar envío cuando el frontend lo puso a 0; entonces `acceptedDiscount` ya no coincide con `appliedDiscount` y se rechazan checkouts legítimos con cupón.
  - confidence: 0.86
- **[P2] Decide el estado de pago después del ajuste FREE_UNITS:** `apps/hamelyn-ecommerce/app/api/v5/checkout/route.ts:713-716`
  - body: `creationPaymentStatus` se decide con el total validado antes de que `adjustTotalForFreeUnitsCoupon` pueda mover `order.totalPrice`. Con la tolerancia por campo, un pedido FREE_UNITS puede quedar guardado como `SUCCEEDED` pero con total final por encima de `FREE_ORDER_TOTAL_TOLERANCE`; después `POST /api/v5/order-sell` responde 202 y no crea el pedido gratuito.
  - confidence: 0.78
- **[P3] Valida `cartId` y `promotionCode` en el esquema Zod:** `apps/hamelyn-ecommerce/app/api/v5/checkout/route.ts:83-95`
  - body: El esquema usa `.passthrough()` pero no tipa `cartId` ni `promotionCode`; si llegan como número u objeto, llamadas posteriores como `cartId?.trim()` pueden lanzar un 500 en lugar de un 400 controlado. Añadirlos como strings opcionales mantiene la frontera Zod que AGENTS.md pide para código nuevo.
  - confidence: 0.82
