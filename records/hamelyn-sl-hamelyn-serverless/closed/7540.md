## Label Justifications

- `P2`: El fallo bloquea la impresión de etiquetas concretas con impacto operativo limitado, sin inutilizar todo el sistema.
- `merge-risk: 🚨 compatibility`: El 404 puede convertir una indisponibilidad temporal en una señal permanente de recurso inexistente para los callers y operadores.

## Summary

Mantener este PR abierto, pero no mergearlo en su estado actual: la evidencia operativa muestra que los fallos observados son lecturas transitorias de blobs existentes, por lo que devolver 404 describe mal el problema y sigue dejando bloqueada la impresión.

## What This Changes

El PR sustituye el error genérico de `materializeLabel` por un `BaseErrorExpected` con estado 404 y código `LABEL_BLOB_NOT_FOUND` cuando no se obtienen bytes del blob ni existe buffer legacy.

## Best Possible Solution

Aplicar retry acotado con backoff a la descarga de Blob y devolver `503 LABEL_TEMPORARILY_UNAVAILABLE` con el `labelId` al agotarlo, reservando 404 para una ausencia confirmada del recurso.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, a nivel de fuente y datos operativos: una respuesta Blob distinta de 200 se convierte en `undefined`, alcanza el error final y el handler actual la transforma en 500. No se ejecutó una reproducción real contra producción durante esta revisión.

## Solution Assessment

No; el 404 mejora la clasificación respecto al 500 genérico, pero no representa la causa transitoria ni recupera la impresión mediante reintento. Retry corto y un 503 esperado constituyen la solución más estrecha y mantenible.
