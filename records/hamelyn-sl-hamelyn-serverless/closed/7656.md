## Summary

La issue sigue siendo necesaria: `dev` no renueva listings antiguos de Discogs y no existe otra issue ni PR que se haya hecho cargo del trabajo. La discusión aporta datos operativos sólidos de viabilidad, pero confirma que aún falta validar la semántica remota mediante canarios.

## What This Changes

Añadir al cron de Discogs una fase que renueve de forma rotacional los listings activos más antiguos aproximadamente cada siete días.

## Best Possible Solution

Ejecutar primero canarios controlados que comparen ID, estado y `posted`; si confirman el relistado in-place, implementar una fase común de selección ordenada con callback específico de Discogs, recuperación explícita del estado intermedio y avance de `lastUpdatedTimestamp` tras cada intento.
