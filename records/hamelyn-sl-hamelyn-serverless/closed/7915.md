## Summary

El PR corrige una señal útil, pero el filtro `stockStatus: ACTIVE` oculta errores de retirada aún reintentables y también errores `PENDING_SKYPOD`; además, el informe incorpora una consulta potencialmente costosa sin límite.

## What This Changes

El PR añade al endpoint v6 un desglose de `SYNC_ERROR` para stock activo y cambia tres consultas del informe de errores para excluir stock retirado.

## Best Possible Solution

Definir una métrica de errores accionables que conserve reintentos de retirada y `PENDING_SKYPOD`, mantenga separado el residuo histórico y documente claramente cada contador.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, desde el código: una fila `WITHDRAWN` con `SYNC_ERROR` y `WITHDRAWNING` entra en el selector de reintentos, pero el nuevo filtro la excluye. Una fila `PENDING_SKYPOD` con `SYNC_ERROR` también queda fuera del nuevo desglose.

## Solution Assessment

No. Filtrar exclusivamente `ACTIVE` no implementa la exclusión de errores históricos retirados porque mezcla con ellos errores pendientes y reintentos de retirada que siguen siendo accionables.
