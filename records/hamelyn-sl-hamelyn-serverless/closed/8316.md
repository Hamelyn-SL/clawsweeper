## Summary

El objetivo no está en `dev` y el PR mantiene un bloqueo de compatibilidad: las rutas cacheadas dejan de poder usar el fallback por host cuando falta la identidad de despliegue. La evidencia de canary es útil, pero hace falta decidir ese contrato antes del merge.

## What This Changes

Migra `apps/hamelyn-ecommerce` a Cache Components de Next 16.3, cambia la resolución de locale y cachés, y añade pruebas E2E con un workflow de CI.

## Best Possible Solution

Mantener el fallback dinámico funcional fuera de los ámbitos `"use cache"`, o aceptar explícitamente que la variable sea obligatoria y documentar una migración verificable para cada despliegue afectado.
