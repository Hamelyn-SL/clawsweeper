## Summary

Gracias por la contribución; el enfoque cubre el caso individual, pero un fallo de otro pedido del mismo lote vuelve a marcar también ese pedido como `SYNC_ERROR`, por lo que el bucle de reintento puede persistir.

## What This Changes

El PR consulta `getOrder` tras fallar `editOrder` y considera completado el envío si Discogs ya devuelve el estado remoto `Shipped`.

## Best Possible Solution

Devolver `MarketplaceShipResult[]` por pedido desde el adaptador de Discogs, preservando `SHIPPED` para el remoto confirmado y aislando los fallos reales.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, por código: combinar un pedido que ya devuelve `Shipped` tras el 422 con otro que falle hace que `runMarketplaceShip` marque ambos como `SYNC_ERROR`. No se ha ejecutado contra Discogs en esta revisión.

## Solution Assessment

No. El fallback debe conservar el resultado por pedido; ignorar el error localmente no basta cuando el orquestador trata cualquier excepción posterior como fallo de todo el lote.
