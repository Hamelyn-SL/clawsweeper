## Summary

El fallo sigue existiendo en `dev`: el cliente compartido de eDesk aún no reintenta `429`, el pipeline puede devolver éxito aunque falle `POST /messages`, y hay una PR abierta con cierre explícito que concentra la reparación. Mantendría esta issue abierta hasta revisar y fusionar o descartar esa PR.

## What This Changes

La issue pide evitar que incidencias de Ecommerce y Supply creen tickets de eDesk sin mensaje visible cuando eDesk responde con rate limit al crear el mensaje.

## Best Possible Solution

Cerrar esta issue automáticamente solo cuando la PR vinculada se fusione o, si se descarta, mantener un fix estrecho que centralice retry/backoff de `429`, propague `subject` a mensajes y devuelva error cuando el mensaje no quede entregado.
