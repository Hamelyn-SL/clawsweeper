## Label Justifications

- `P0`: El acceso no autenticado permite leer o modificar carritos de terceros en una ruta activa de Supply.
- `impact:security`: El problema rompe el límite de autorización al tratar un identificador de carrito como prueba de posesión.

## Summary

Mantener abierta: `dev` sigue exponiendo el carrito por `cartId`, y la PR vinculada aún necesita una decisión de transición segura y prueba actualizada antes de poder cerrar el IDOR.

## What This Changes

La incidencia solicita reemplazar la posesión basada en `cartId` por una capability opaca para proteger todas las operaciones del carrito Supply.

## Best Possible Solution

Exigir capability de inmediato para cualquier carrito asociado a usuario y limitar una transición temporal, si se acepta, exclusivamente a anónimos sin hash con corte aplicado por servidor.

## Solution Assessment

No del todo. La capability es el enfoque adecuado, pero la compatibilidad legacy debe impedir desde el principio el acceso tokenless a carritos asociados a usuarios.
