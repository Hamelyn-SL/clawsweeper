## Label Justifications

- `P2`: La mejora automatiza releases de Supply, con impacto operativo importante pero sin evidencia de una incidencia inmediata en producción.
- `merge-risk: 🚨 compatibility`: El bump deja sin actualizar versiones que el proyecto nativo actual todavía declara y compila.
- `merge-risk: 🚨 security-boundary`: El workflow combina un token de EAS con permiso de escritura y push a la ref seleccionada.
- `merge-risk: 🚨 automation`: La concurrencia y el orden de commit/build pueden producir bumps publicados aunque el despliegue falle.

## Summary

El PR sigue siendo necesario para la automatización de EAS, pero el workflow puede publicar versiones incompletas y necesita una decisión explícita sobre la frontera de release antes de poder integrarse.

## What This Changes

El PR añade un workflow manual de EAS Build + Submit para Supply, perfiles beta/release, un script de bump de versión y documentación operativa.

## Best Possible Solution

Definir una rama de release autorizada, generar y sincronizar las versiones nativas antes del build, y publicar el commit solo después de una beta aceptada y demostrada.
