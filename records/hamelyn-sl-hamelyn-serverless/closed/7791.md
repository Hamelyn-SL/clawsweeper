## Label Justifications

- `P1`: El workflow de lifecycle puede dejar veredictos de Proof Agent obsoletos durante revisiones activas.
- `impact:other`: El efecto es fiabilidad operativa del feedback automatizado de PRs, fuera de las categorías de impacto más específicas.

## Summary

La incidencia sigue vigente en `dev`: el endpoint espera la prueba completa antes de responder y el feedback se publica al final. Existe un candidato abierto en https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7794, pero su propia prueba identifica que aún no cumple la cancelación ni el feedback terminal por ejecución.

## What This Changes

Corregir el Proof Agent para aceptar cada ejecución con HTTP 202, publicar `EN CURSO` al inicio y terminar con un estado final visible.

## Best Possible Solution

Completar el PR enlazado con un job durable e idempotente por `PR + headSha + run`, cancelación o invalidación cooperativa, y un cierre CAS que publique siempre veredicto, `infrastructure_error` u `OBSOLETO`.
