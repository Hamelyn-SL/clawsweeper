## Summary

Keep open: current dev still stores and filters warehouse productivity as generic `PICKING` and `PACKING`, and the latest discussion changed this into an unresolved product choice between visual, metadata, or enum/schema approaches.

## What This Changes

The issue requests measuring Picking and Packing productivity separately by real warehouse subtypes instead of only the generic `PICKING` and `PACKING` operation types.

## Best Possible Solution

Choose a product model first, preferably persisted `metadata.operationSubtype` with derived historical fallback, then implement it end-to-end for tracker updates, sanitization, list filtering, and dashboard aggregation without changing `operationType` unless maintainers explicitly want that migration.
