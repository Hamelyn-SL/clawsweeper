## Summary

Debe seguir abierta: `dev` todavía genera GIF/PNG, publica siempre en Vercel Blob y no contiene un adaptador para adjuntos nativos de GitHub. La prueba E2E aportada confirma que la subida con una sesión de desarrollo es viable, pero aún faltan la integración segura, el fallback monitorizado y la gestión de expiración.

**Personas probablemente relacionadas**

- `MiguelHamelyn` — fusionó la implementación original de PR Proof; confianza media.

## What This Changes

Publicar las evidencias de PR Proof como WebM e imágenes mediante adjuntos nativos de GitHub, conservando Vercel Blob como fallback seguro e idempotente.

## Best Possible Solution

Separar generación y transporte: producir WebM en el modo navegador y añadir un adaptador server-only, reversible y opt-in para una sesión dedicada de GitHub, con cifrado, health-check, rotación, alertas, fallback automático a Blob y pruebas E2E de WebM, PNG, expiración e idempotencia.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: ¿Autorizamos que Marketplace Agents mantenga una sesión dedicada de GitHub para subir adjuntos mediante una interfaz no documentada, bajo aislamiento server-only y fallback a Vercel Blob?

Rationale: La implementación exige custodiar una credencial de sesión potencialmente amplia y asumir la estabilidad operativa de un mecanismo sin contrato REST público; el código no puede decidir ese límite de seguridad y soporte por sí solo.

Likely owner: JavierHamelyn

Owner reason: Es la persona asignada, autora de PR Proof y de las mejoras recientes de seguridad de esta superficie.

Owner confidence: high

Options:

- **Piloto aislado y reversible (recommended):** Autorizar una cuenta dedicada y un adaptador opt-in con privilegios mínimos, rotación, health-check, alertas y fallback inmediato a Blob.
- **Mantener únicamente Blob:** Generar WebM para reducir peso, pero conservar Vercel Blob como único transporte hasta disponer de una API oficial estable.
- **Esperar soporte oficial:** Pausar la subida nativa y reevaluar la mejora cuando GitHub publique un endpoint soportado para adjuntos.

## Reproduction Assessment

No aplica como reproducción de un bug: es una nueva capacidad. El comentario E2E demuestra la viabilidad de una subida nativa con una sesión de desarrollo, mientras que la inspección de `dev` confirma que la integración aún no existe.

## Solution Assessment

La dirección técnica es razonable, pero todavía no puede considerarse la mejor solución sin aprobar el límite de seguridad. La opción más mantenible es un transporte abstraído y opt-in, con cuenta dedicada y Blob como fallback, no sustituir incondicionalmente el mecanismo actual.
