## Label Justifications

- `P1`: El run diario de detección queda bloqueado por el límite facturable y la implementación propuesta puede mantener ese fallo.
- `merge-risk: 🚨 availability`: Un scan no compartido puede hacer que el scheduler diario siga fallando antes de detectar actividad de scraping.
- `merge-risk: 🚨 other`: El límite temporal de 300 GiB puede aumentar el coste operativo si el plan continúa leyendo la tabla tres veces.

## Summary

Este PR aborda un fallo real del watcher, pero la consulta propuesta conserva tres scans independientes y no demuestra el ahorro de BigQuery antes de elevar el límite a 300 GiB.

## What This Changes

Sustituye tres detectores del `scraping-watcher` por `detectPrecheck()`, ajusta el deduplicado WAF, eleva temporalmente los límites de BigQuery y amplía pruebas y documentación.

## Best Possible Solution

Construir un precheck que lea `vercel_logs.events` una sola vez mediante una materialización o plan verificablemente compartido, conservar los tres clasificadores y adjuntar una ejecución real de BigQuery con bytes, duración y resultados redactados.
