## Label Justifications

- `P1`: Los timeouts recurrentes impiden completar un cron operativo que actualiza precios periódicamente.
- `impact:other`: El impacto concreto es el retraso de actualizaciones de precio, sin evidencia de pérdida de datos ni de una caída general del proceso.

## Summary

La incidencia sigue siendo necesaria: el controlador actual procesa el lote completo sin presupuesto temporal y actualiza `lastPriceAttempt` antes de despachar los productos, por lo que el ajuste externo de tamaño no elimina el riesgo de `504`.

## What This Changes

Evitar que el cron `/api/update-price-product` agote su runtime y devuelva `504` recurrentes al actualizar precios.

## Best Possible Solution

Mantener un lote configurable, pero dejar de despachar antes de un presupuesto conservador y marcar `lastPriceAttempt` únicamente para cada producto ya enviado al proveedor.

Required: false

## Reproduction Assessment

Sí, por fuente: ejecutar un lote que supere el tiempo disponible reproduce el camino sin deadline, y el marcado anticipado confirma que los elementos pendientes quedan afectados.

## Solution Assessment

Sí: un presupuesto temporal independiente del tamaño de lote ataca la causa del timeout y conserva la configuración de capacidad como ajuste secundario.
