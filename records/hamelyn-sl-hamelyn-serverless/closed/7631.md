## Summary

Este PR sigue siendo necesario y aborda una carencia real de `dev`, pero no está listo para merge: el caso de tabla ausente falla por una carrera con `bq-merge`, las ejecuciones pueden colisionar sobre la misma staging y el workflow puede cancelar Dataflows todavía activos.

## What This Changes

El PR centraliza el registro de colecciones Mongo→BQ y añade un job de despliegue que detecta y siembra baselines mediante Dataflow.

## Best Possible Solution

Asegurar la tabla final antes del volcado, serializar los seeds por entorno, aislar la staging de cada ejecución o implementar cleanup y cancelación robustos, y ejecutar Dataflow con una identidad dedicada de mínimo privilegio.
