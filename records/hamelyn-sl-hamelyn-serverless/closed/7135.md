- `impact:security`: El issue trata una frontera de confianza: el backend persiste un descuento enviado por el cliente para varios tipos de cupón.

## Summary

Debe seguir abierta: en `dev` el checkout todavía copia `appliedDiscount` del cliente y solo lo sustituye por el cálculo del servidor cuando `unitsGranted` existe, mientras que la PR enlazada que cierra el problema sigue abierta.

## What This Changes

El issue pide que el checkout recalcule o contraste en servidor el descuento aplicado para todos los tipos de cupón, no solo para cupones `FREE_UNITS`.

## Best Possible Solution

Revisar y aterrizar https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7157, o sustituirla por un fix equivalente que use el descuento validado en servidor para todos los tipos de cupón y mantenga coherente `totalPrice`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, por inspección de fuente: `route.ts` copia `checkoutNewOrder.appliedDiscount` y solo lo sustituye cuando la validación devuelve `unitsGranted`, mientras `isCouponValid` calcula `discount` para otros tipos de cupón.

## Solution Assessment

Sí: la solución más estrecha es reutilizar `couponValidation.discount` al construir el pedido para cualquier cupón válido, conservando `unitsGranted` como dato específico de `FREE_UNITS` y validando la coherencia de `totalPrice`.
