## Label Justifications

- `P1`: El cron diario de avisos puede perder/envíar tarde notificaciones reales de disponibilidad por una configuración de producción ausente.
- `impact:message-loss`: La incidencia afecta al envío de emails de disponibilidad pendientes a usuarios cuando el cron no puede consultar stock.

## Summary

Mantendría esta issue abierta: el código actual sigue fallando si `STOCK_KV_REST_API_URL` o `STOCK_KV_REST_API_TOKEN` faltan, y la evidencia disponible apunta a una corrección operativa pendiente en Vercel, no a algo ya implementado en `dev`.

## What This Changes

El reporte pide corregir el fallo del cron `/api/notify-availability` cuando el proyecto `crons` no tiene configuradas las variables `STOCK_KV_*`.

## Best Possible Solution

Propagar `STOCK_KV_REST_API_URL` y `STOCK_KV_REST_API_TOKEN` al proyecto Vercel `crons` producción y reejecutar `/api/notify-availability`; cualquier fallback de código debería tratarse como decisión de arquitectura separada.
