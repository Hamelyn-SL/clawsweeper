## Summary

La issue sigue siendo necesaria: `dev` todavía genera `MERGE` directo contra `hamelyn-data.mongodb.<colección>` sin auto-crear la tabla destino, y hay un PR abierto con sintaxis de cierre que debe revisarse antes de cerrar la issue.

## What This Changes

La issue pide que `hamelyn-bq-merge` cree las tablas raw `mongodb.*` que falten antes de ejecutar cada `MERGE`, para evitar fallos en cascada del merge horario.

## Best Possible Solution

Revisar y aterrizar `https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7283`, incluyendo la auto-creación de tablas y el alta de las colecciones marketplace que faltan, y cerrar esta issue solo cuando el cambio esté en `dev`.

Sí: por inspección de código en `dev`, basta añadir una colección nueva a `MERGE_COLLECTIONS` sin tabla raw previa para que el SQL generado haga `MERGE` contra una tabla inexistente dentro de un único bloque `BEGIN`.
