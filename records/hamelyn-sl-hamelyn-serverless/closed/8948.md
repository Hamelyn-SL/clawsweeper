## Summary

Gracias por la contribución. El problema sigue presente en `dev` y este PR aporta una solución acotada, con dry-run provisional y tres barreras para impedir cualquier ejecución no registrada.

## What This Changes

El PR genera dry-runs B2B para pedidos de clientes no registrados, deriva un perfil provisional del título y bloquea la ejecución hasta registrarlos en `B2B_CLIENTS`.

## Best Possible Solution

Aterrizar el perfil provisional exclusivamente en la fase de cálculo, manteniendo las barreras de autorización, tool HITL y `executeOrder` junto con la sincronización del ledger.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, por código: `dev` actual lanza `unknown client for selection` antes de descargar, parsear o seleccionar stock para un cliente no registrado.

## Solution Assessment

Sí. La separación entre perfil provisional de solo lectura y cliente registrado ejecutable es la vía más estrecha y conserva el fail-closed de las mutaciones.
