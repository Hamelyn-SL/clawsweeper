## Summary

La incidencia sigue vigente: `dev` declara y resuelve `xlsx@0.18.5`, mientras rutas autenticadas de Admin entregan archivos XLSX a `XLSX.read()`. Falta una decisión de seguridad sobre la procedencia del tarball corregido antes de aplicar la remediación común.

## What This Changes

Actualizar las dependencias directas de Admin y Core desde `xlsx@0.18.5` para corregir la contaminación de prototipos al leer XLSX no confiables.

## Best Possible Solution

Aprobar una fuente de suministro verificada, fijar una versión corregida e inmutable en Admin y Core, regenerar el lockfile y validar las rutas de importación y generación XLSX afectadas.
