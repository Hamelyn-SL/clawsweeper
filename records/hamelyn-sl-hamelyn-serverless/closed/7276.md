## Label Justifications

- `P2`: La mejora afecta a automatización interna de PRs y visibilidad de estado, con impacto acotado a infraestructura de notificaciones.
- `impact:ux-friction`: La falta de hilo y badge obliga al equipo a abrir contexto o inferir el estado de cada PR en Slack, pero no bloquea un flujo crítico.

## Summary

La issue sigue siendo necesaria: en `dev` la notificación de PRs continúa saliendo como webhook suelto y no existe el script pedido para guardar `ts`, publicar en hilo ni reconciliar una reacción de estado. El patrón equivalente para issues/wishlist sí existe y sirve como base, pero todavía no está aplicado a PRs.

## What This Changes

La issue pide migrar las notificaciones de PRs de `#github-noty` a bot token con hilo por PR, replies por eventos de revisión/cierre/merge y una reacción de estado en el mensaje raíz.

## Best Possible Solution

Añadir un script dedicado de PRs que reutilice el patrón probado de issues, mantener `pr-review-reminder.yml` separado y validar root, replies y reacción con un run real redactado.
