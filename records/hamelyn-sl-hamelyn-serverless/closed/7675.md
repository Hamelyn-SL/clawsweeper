## Label Justifications

- `P2`: El fallo bloquea una automatización interna útil, pero el kill-switch está activo y la resolución manual de conflictos sigue disponible.
- `impact:other`: El impacto concreto es que la automatización no alcanza la validación, el merge commit ni el push, sin encajar en las categorías específicas de pérdida de datos, mensajes, sesión, autenticación o disponibilidad.

## Summary

Debe seguir abierta: `dev` todavía lanza el bootstrap sin fijar su directorio de trabajo y abre los manifiestos mediante rutas relativas, por lo que el mismo workspace válido funciona desde la raíz del repositorio pero se convierte en `unsafe` con `ENOENT` desde otro `cwd`. https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7673 registró el fallo dos veces contra revisiones distintas de `dev`; https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7685 demuestra que una corrección en Preview puede completar el merge, pero era una PR temporal de prueba y no incorporó el arreglo a `dev`.

## What This Changes

Corregir el mapeo de workspaces del resolvedor cloud para que use la raíz real del checkout, preserve el diagnóstico y cubra rutas válidas e inseguras con tests.

## Best Possible Solution

Extraer el mapeo a una unidad comprobable que obtenga la raíz con `git rev-parse --show-toplevel`, resuelva manifiestos mediante rutas absolutas y emita `cwd`, workspace y error original; cubrir `apps/*`, `packages/*` y rutas inseguras, y mantener el kill-switch hasta repetir una prueba temporal end-to-end tras integrar el cambio.
