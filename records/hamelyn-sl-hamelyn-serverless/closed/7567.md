## Label Justifications

- `P1`: El defecto retrasa de forma recurrente hasta 14 días la publicación de stock vendible en un marketplace activo.
- `impact:other`: La incidencia reduce de forma medible la disponibilidad comercial del inventario, sin corresponder a las categorías específicas de pérdida de datos, mensajes, sesión, autenticación, seguridad o caída del proceso.

## Summary

La issue sigue siendo necesaria: el `dev` actual aún aplica un cooldown de 14 días a `DUPLICATE_ACTIVE_LISTING` y no promueve otra copia vendible al desaparecer el listing canónico. El PR https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7577 es el candidato directo, pero continúa abierto, así que la issue debe permanecer abierta hasta que se fusione o se descarte.

## What This Changes

Corregir la reconciliación de MercadoLibre para reencolar inmediatamente una única copia vendible cuando un EAN deja de tener un listing activo.

## Best Possible Solution

Fusionar una implementación que detecte los EAN liberados antes de `create`, reencole de forma atómica una sola copia vendible y conserve los guardas existentes de EAN activo, deduplicación de lote y rechazo remoto; después, verificar con datos reales que baja el backlog sin aparecer listings duplicados.

## Reproduction Assessment

Sí, hay una vía de reproducción de alta confianza mediante fuente y datos operativos: `dev` mantiene el cooldown de 14 días, cada rechazo renueva el timestamp y el triage documenta las mismas candidatas entrando repetidamente en ese ciclo. No se mutó producción durante esta revisión de solo lectura.

## Solution Assessment

Sí, la dirección del PR enlazado es la solución más estrecha: liberar una sola copia cuando el EAN queda realmente libre preserva la deduplicación, frente a eliminar globalmente el cooldown o el guard. Antes de fusionarlo debe confirmarse su comportamiento ante carreras entre selección, subida, venta y retirada.
