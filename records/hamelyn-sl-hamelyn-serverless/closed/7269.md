Full review comments:

- **[P1] Fija la versión del CLI de Vercel antes de usar el token:** `.github/workflows/cli-release.yml:98-102`
  - body: Este workflow ejecuta `npx --yes vercel@54` en un job de release que recibe `CLI_BLOB_READ_WRITE_TOKEN`. Como `vercel@54` puede resolver a una nueva versión 54.x en futuros tags, una actualización o compromiso de esa dependencia ejecutaría código no revisado con permiso de escritura sobre el canal de distribución del CLI. Pincha una versión exacta/verificada o usa una acción/herramienta controlada antes de publicar binarios.
  - confidence: 0.9
- **[P1] Evita escribir un elemento vacío en el PATH de usuario:** `apps/api/public/cli/install.ps1:28`
  - body: Si el `Path` de usuario no existe o está vacío, esta línea guarda `;$BinDir`. En Windows, un elemento vacío en PATH puede hacer que se busque en el directorio actual, así que el instalador debería escribir solo `$BinDir` cuando `$UserPath` esté vacío y concatenar con `;` únicamente cuando ya haya contenido.
  - confidence: 0.87
- **[P2] Sincroniza el lockfile con la versión 0.4.0:** `apps/hamelyn-cli/Cargo.lock:981-1012`
  - body: El manifest del workspace fija `version = "0.4.0"`, pero `Cargo.lock` registra los paquetes locales `hamelyn` y `hamelyn-client` como `0.4.1`. Eso deja el lockfile desalineado con la release `cli-v0.4.0` descrita por el PR y puede romper ejecuciones con `--locked` o generar churn automático en el siguiente `cargo`.
  - confidence: 0.78
